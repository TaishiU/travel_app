### 1. `_saveTokens()` が空 accessToken でも SuccessResult を返す【Critical】

**箇所**: `lib/data/repositories/auth/auth_repository_impl.dart` (62〜84行目、213〜221行目)

`login()` / `register()` はサーバーが 200 を返した場合、`_saveTokens()` の結果に関わらず `SuccessResult(null)` を返す。
しかし `_saveTokens()` は `dto.accessToken` が null/空のとき `_isLoggedIn = false` を設定するだけで、呼び出し元に失敗を伝えない。

```dart
// auth_repository_impl.dart:213-221
Future<void> _saveTokens({required TokenResponseDto dto}) async {
  await _persistTokenPair(
    accessToken: dto.accessToken ?? '',
    refreshToken: dto.refreshToken ?? '',
  );
  await _persistUserId(userId: dto.user?.id ?? '');
  _isLoggedIn = (dto.accessToken ?? '').isNotEmpty; // ← false になる
  _isLoaded = true;
  // ↑ 呼び出し元 login() は構わず SuccessResult(null) を返す
}
```

**影響シーケンス:**
1. API が 200 + `accessToken: null` を返す（サーバーバグ・仕様変動）
2. `_saveTokens()` → `_isLoggedIn = false` を設定
3. `login()` → `notifyListeners()` → `SuccessResult(null)` を返す
4. `AuthUseCase.login()` → `SuccessResult(pendingDeepLink)` を返す
5. `LoginScreenNotifier` → `state = AsyncData(LoginScreenState())` — エラーなし
6. Router redirect → `isLoggedIn = false` → リダイレクトなし
7. **ユーザーはフィードバックなしにログイン画面に留まる（サイレント失敗）**

**影響**: ログイン成功の invariant（`SuccessResult` = 認証済み）が破れる。DTO nullable 設計（サーバー仕様変動対応）と組み合わさると、サーバー側の軽微な変更でも本番で再現しうる。

**再現手順:**

```dart
// flutter test test/data/repositories/auth/auth_repository_impl_defect_test_original.dart
// 欠陥1 テスト1: FailureResult を期待するが SuccessResult が返り失敗する
// 欠陥1 テスト2: SuccessResult かつ isLoggedIn = false という矛盾状態を確認（通過）

test(
  'APIが accessToken: null を返した場合、login() は FailureResult を返すべき',
  () async {
    // accessToken: null を返すスタブ（StubAuthApiServiceImpl の代替）
    final repository = AuthRepositoryImpl(
      authApiService: _NullAccessTokenAuthApiService(), // test ファイル内定義
      authSecureStorageService: authStorage,
      idGenerator: () => 'test-id',
    );

    final result = await repository.login(
      email: 'test@example.com',
      password: 'password',
    );

    // 欠陥: 現状 SuccessResult(null) が返るため失敗する
    expect(result, isA<FailureResult<void>>());
  },
);
```

スタブ定義・フルテストコード: `test/data/repositories/auth/auth_repository_impl_defect_test.dart`

### 2. `_handleTokenRefresh()` 失敗時に `AuthRepository` を通知しないため `_isLoggedIn` が陳腐化する【Critical】

**箇所**: `lib/data/services/web_api/api_client.dart` (428〜444行目)

`ApiClientImpl._handleTokenRefresh()` はリフレッシュトークンの有効期限切れなど失敗時に `clearAuthData()` を呼んでトークンを削除するが、`AuthRepositoryImpl.notifyListeners()` を呼ばない。そのため `AuthRepositoryImpl._isLoggedIn` が `true` のまま陳腐化し、GoRouter の redirect が再評価されずログイン画面へ遷移しない。

```dart
// api_client.dart:428-444
if (response.statusCode == 200) {
  // ... トークン保存 ...
  return true;
} else {
  await authSecureStorageService.clearAuthData(); // ← トークン削除
  return false;
  // notifyListeners() は一切呼ばれない
}
```

**影響シーケンス:**
1. アクセストークン期限切れ → `_handleTokenRefresh()` が `auth/refresh` を呼ぶ
2. リフレッシュトークンも期限切れ → 200 以外が返る
3. `clearAuthData()` → ストレージとインメモリのトークンが削除される
4. `_handleTokenRefresh()` → `false` を返す
5. `_safeApiCall()` → `throw UnauthorizedException('Session expired')`
6. BUT: `AuthRepositoryImpl._isLoggedIn` は `true` のまま、`notifyListeners()` 未発火
7. GoRouter の redirect は再評価されずログイン画面へ遷移しない
8. **`isLoggedIn` はキャッシュ値 `true` を返し続け、全 API 呼び出しが 401 で失敗し続ける**
9. ユーザーは手動ログアウトしない限り復帰できない（アプリ再起動で回復）

**影響**: セッション切れに気づけないまま全 API が失敗し続ける。ユーザーは操作不能状態になるが、ログイン画面へ誘導されない。

**再現手順:**

```dart
// flutter test test/data/repositories/auth/auth_repository_impl_defect_test_original.dart
// 欠陥2 テスト: isLoggedIn = false を期待するが true が返り失敗する

test(
  'ApiClient がリフレッシュ失敗時に clearAuthData() を呼んだ後、isLoggedIn が false を返すべき',
  () async {
    final repository = AuthRepositoryImpl(
      authApiService: StubAuthApiServiceImpl(),
      authSecureStorageService: authStorage,
      idGenerator: () => 'test-id',
    );

    // ログインして _isLoggedIn = true（インメモリキャッシュ）にする
    await repository.login(email: 'test@example.com', password: 'password');
    expect(await repository.isLoggedIn, isTrue);

    // ApiClientImpl._handleTokenRefresh() がリフレッシュ失敗時に行う操作を再現:
    //   clearAuthData() でストレージのトークンを削除するが notifyListeners() を呼ばない
    await authStorage.clearAuthData();

    // 欠陥: _isLoggedIn のインメモリキャッシュが true のまま残るため失敗する
    expect(await repository.isLoggedIn, isFalse);
  },
);
```

スタブ定義・フルテストコード: `test/data/repositories/auth/auth_repository_impl_defect_test_original.dart`

### 付記: `AuthRepositoryImpl.refreshToken()` は呼び出し元ゼロの死にコード

`AuthRepositoryImpl.refreshToken()` はインターフェースに定義・実装されているが、現在の呼び出し元が存在しない（実際のリフレッシュは `ApiClientImpl._handleTokenRefresh()` が直接 HTTP 呼び出しで実施）。将来呼び出された場合、空 accessToken でも `SuccessResult` を返す（Issue 1 と同パターン）かつ `notifyListeners()` を呼ばないため、Issue 1・2 を複合した状態に陥る。

## 結論

Critical 3件（Issue 1・2 + 付記）。

## 妥当性

### 1. `_saveTokens()` が空 accessToken でも SuccessResult を返す
**判断**: Critical（修正対象）
**根拠**: `auth_repository_impl.dart:62-84` の `login()` は `_saveTokens()` 呼出後に無条件で `SuccessResult(null)` を返す。`_saveTokens()` は `void` を返すため呼び出し元に失敗を伝える手段がない。再現テストで `SuccessResult` が返ることを確認済み。DTO の全フィールドが nullable 設計であり、サーバー側の軽微な変更で実際に発生しうる。

### 2. `_handleTokenRefresh()` 失敗時に `_isLoggedIn` が陳腐化する
**判断**: Critical（修正対象）
**根拠**: `isLoggedIn` getter（:53-59行）は `_isLoggedIn != null && _isLoaded` の場合にインメモリキャッシュを返す。`clearAuthData()` は `AuthSecureStorageServiceImpl._accessToken = ''` を更新するが、`AuthRepositoryImpl._isLoggedIn` キャッシュは更新されない。再現テストで `clearAuthData()` 後も `true` が返ることを確認済み。

### 付記: `refreshToken()` 死にコード
**判断**: 技術的負債（修正対象）
**根拠**: `AuthRepositoryImpl.refreshToken()` は `AuthRepository` インターフェースに定義・実装されているが、codebase 内の呼び出し元がゼロ。また `accessToken` が空でも `SuccessResult(null)` を返す（Issue 1 と同パターン）かつ `notifyListeners()` 欠如を抱えており、将来呼ばれた際に Issue 1・2 の複合欠陥が再現する。

## 修正方針

### 1. `_saveTokens()` が空 accessToken でも SuccessResult を返す（Critical）
**変更ファイル**: `lib/data/repositories/auth/auth_repository_impl.dart`
**方針**: `_saveTokens()` 内で `accessToken` / `refreshToken` のいずれかが空の場合に `InternalServerErrorException` を throw する。`login()`/`register()` の `on Exception catch` ブロックがキャッチし `FailureResult(AppError.from(error))` → `ServerError(500)` を返す。throw されなかった = 両トークン非空が保証されるため `_isLoggedIn = true` 固定に変更。
**テスト更新**: 要 — 異常系（accessToken / refreshToken が null）のテストを `auth_repository_impl_test.dart` に追加

### 2. `isLoggedIn` が陳腐化したキャッシュを返す（Critical）
**変更ファイル**: `lib/data/repositories/auth/auth_repository_impl.dart`
**方針**: `isLoggedIn` getter を修正し、`_isLoaded` 済みの場合も `_loadLoginState()` を呼んで `authSecureStorageService.getAccessToken()` から最新値を取得する。`getAccessToken()` は `AuthSecureStorageServiceImpl` のインメモリ値（実I/Oなし）を返すためパフォーマンス影響はない。
**テスト更新**: 不要 — 再現テストがカバー済み

### 付記: `refreshToken()` / `AuthApiService.refresh()` 全削除（技術的負債）
**変更ファイル**:
- `lib/domain/interfaces/auth/auth_repository.dart` — `refreshToken()` 削除
- `lib/data/repositories/auth/auth_repository_impl.dart` — `refreshToken()` 削除
- `lib/data/services/web_api/auth/service.dart` — `refresh()` 削除
- `lib/data/services/web_api/auth/service_impl.dart` — `refresh()` 削除
- `lib/data/services/web_api/auth/stub_service_impl.dart` — `refresh()` 削除
- `lib/data/services/web_api/auth/dto.dart` — `RefreshTokenDto` 削除（唯一の使用箇所が `AuthApiService.refresh()` のみ）
- `lib/data/services/web_api/auth/dto.freezed.dart` / `dto.g.dart` — コード再生成

**方針**: 呼び出し元ゼロの死にコードを完全削除する。`ApiClientImpl._handleTokenRefresh()` は `auth/refresh` エンドポイントを直接呼んでおり `AuthApiService.refresh()` を経由しないため、インターフェースに残すと「Repository 経由でリフレッシュできる」という誤解を招く。
**テスト更新**: 不要 — 呼び出し元ゼロのため既存テストへの影響なし
