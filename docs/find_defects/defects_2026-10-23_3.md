### 1. ログイン/登録失敗時に `_navigateAfterAuth` が無条件発動【Critical】

**箇所**: `lib/presentation/login/screen.dart` (135〜141行目、195〜201行目)

`notifier.login()` / `notifier.register()` の戻り値 `Future<String?>` は、成功+pendingPathなしと失敗の両方で `null` を返す。`_LoginForm` / `_RegisterForm` の `onPressed` は戻り値のみで判断しているため、失敗時でも `_navigateAfterAuth(pendingPath: null)` が呼ばれる。

```dart
// screen.dart:135-141 — 失敗時も同一パスを通る
final pendingPath = await notifier.login(
  email: emailController.text,
  password: passwordController.text,
);
if (!context.mounted) return;
_navigateAfterAuth(context: context, pendingPath: pendingPath); // 失敗時も実行される
```

```dart
// screen.dart:88-99 — pendingPath == null 時の分岐
void _navigateAfterAuth({...}) {
  if (pendingPath != null && pendingPath.isNotEmpty) {
    context.go(pendingPath);
  } else if (context.canPop()) {
    context.pop();          // LoginScreen が push で開かれている場合
  } else {
    context.go(TaskScreen.path); // LoginScreen がスタックルートの場合
  }
}
```

**影響シーケンス:**
1. ユーザーが誤ったパスワードでログインボタンをタップ
2. `notifier.login()` → `FailureResult` → `state = AsyncError(...)` → `return null`
3. `onPressed` が `pendingPath = null` を受け取り `_navigateAfterAuth(pendingPath: null)` を呼ぶ
4a. `context.canPop() == true`（LoginScreen が `push` で開かれた場合）: `context.pop()` → 認証失敗なのに LoginScreen が閉じる
4b. `context.canPop() == false`（LoginScreen が `go` でスタックルートの場合）: `context.go(TaskScreen.path)` → 未認証のまま TaskScreen へ遷移

**影響**: 認証失敗ユーザーが画面遷移でき、未認証状態で保護画面(Phase 3実装後)や通常画面へ到達できる。`register` も同一の構造的欠陥を持つ。

**再現手順:**

```dart

      final container = buildContainer(shouldFail: true)
        ..listen(loginScreenProvider, (_, _) {});
```

## 妥当性

### 1. ログイン/登録失敗時に `_navigateAfterAuth` が無条件発動
**判断**: Critical（修正対象）
**根拠**: `notifier.dart:39-43` にて `FailureResult` 時は `state = AsyncError(...)` をセットし `return null` する。`screen.dart:135-141` の `_LoginForm.onPressed` は `pendingPath == null` であっても `_navigateAfterAuth` を呼ぶ実装になっており、失敗時も画面遷移が発動する。`_RegisterForm`（195-201行目）も同一構造。再現テスト `expect(returnValue, isNotNull)` が失敗し欠陥の存在を証明済み。`LoginScreen` はタスク画面未認証ガードの push ルートとして現実の呼び出しシーケンスに存在する。

---

## 修正方針

### 1. ログイン/登録失敗時に `_navigateAfterAuth` が無条件発動（Critical）
**変更ファイル**: `lib/presentation/login/screen.dart`
**方針**: `_LoginForm` と `_RegisterForm` の `onPressed` で `notifier.login()`/`notifier.register()` 呼び出し後、`ref.read(loginScreenProvider) is AsyncError` の場合は `return` して `_navigateAfterAuth` を呼ばない。Notifier の戻り値ではなく state を正の情報源として利用する（architecture.md の SSOT 原則に沿う）。Notifier の戻り値・型は変更不要。
**テスト更新**: 要（再現テストグループ `'login (戻り値と成功/失敗の区別)'` を削除する。修正は screen.dart 側の state チェック追加であり、notifier は `null` を返し続けるため再現テストの `expect(returnValue, isNotNull)` は通過不可。再現テストは欠陥存在証明用の一時テストであり削除が適切）。
