### 1. `logout()` 部分失敗 — `logoutSession()` 例外時に `notifyListeners()` 未発火【Critical】

**箇所**: `lib/data/repositories/auth/auth_repository_impl.dart` (157–164行目)

`logout()` は内部で `clearAuthData()` → `_issueNewAnonymousId()` を順に `await` するが、`_issueNewAnonymousId()` 内の `logoutSession()` が例外を投げた場合、後続の `_isLoggedIn = false` と `notifyListeners()` に到達しない。

`logoutSession()` は `_brazePlugin.logout()` を返す（`Future<void>` を `await`）。MethodChannel 経由の呼び出しは `PlatformException` を投げることがあり、これは `Exception` のサブクラスである。

```
logout()
  ↓ await _callLogoutApi()       … 例外は on Exception catch で握りつぶす（意図的）
  ↓ await clearAuthData()        … アクセストークン・リフレッシュトークン消去 → 成功
  ↓ await _issueNewAnonymousId() … logoutSession() が PlatformException → 例外伝播
  × _isLoggedIn = false          … 到達しない
  × notifyListeners()            … 到達しない
```

**影響シーケンス:**

1. ユーザーがログアウトボタンをタップ
2. `clearAuthData()` 成功 → ストレージ上のトークン消去
3. `logoutSession()` が `PlatformException` → 例外が `logout()` 外に伝播
4. Notifier が例外をキャッチ（`AsyncError` 状態）
5. `ChangeNotifier.notifyListeners()` 未発火 → ナビゲーション更新なし
6. UI: ログイン済み画面のまま固まる（トークンは無い）
7. 以降の API 呼び出しはすべて 401 になるが画面は遷移しない
8. アプリ再起動まで回復不可（再起動時は `_isLoaded=false` → `_loadLoginState()` でストレージから `false` を読み直し自己修復）

**影響**: ストレージ上はログアウト済みだが UI はログイン済み画面に固まる。ユーザーは再起動なしに操作不能状態から抜け出せない。`_callLogoutApi()` が `on Exception catch` で握りつぶすのと非対称な設計になっている。

## 妥当性

### 1. `logout()` 部分失敗 — `logoutSession()` 例外時に `notifyListeners()` 未発火
**判断**: Critical（修正対象）
**根拠**: `auth_repository_impl.dart:157–164` の `logout()` は `_issueNewAnonymousId()` を `await` した後に `_isLoggedIn = false` と `notifyListeners()` を呼ぶ。`_issueNewAnonymousId()` は内部で `await userIdentityService.logoutSession()` を呼び（262行目）、`logoutSession()` は `_brazePlugin.logout()` を `MethodChannel` 経由で実行するため `PlatformException` を投げうる。`_callLogoutApi()` は同様のリスクに対して `on Exception catch` で握りつぶす設計になっているが、`_issueNewAnonymousId()` には同等のガードがない。ユーザーがログアウトボタンをタップする通常の操作でこの経路は発生しうるため Critical と判断。

## 修正方針

### 1. `logout()` 部分失敗 — `logoutSession()` 例外時に `notifyListeners()` 未発火（Critical）
**変更ファイル**: `lib/data/repositories/auth/auth_repository_impl.dart`
**方針**: `logout()` 内で `_issueNewAnonymousId()` を `try { ... } on Exception catch (error) { logger.e(...); }` で囲み、例外が発生しても後続の `_isLoggedIn = false` / `notifyListeners()` が必ず実行されるようにする。`_callLogoutApi()` と対称な設計にする。
**テスト更新**: 要 — `_ThrowingLogoutUserIdentityService` スタブを既存テストファイルに追加し、`logoutSession()` が例外を投げた場合でも `notifyListeners()` が発火することを確認するテストを `logout 異常系` グループに追記する。
